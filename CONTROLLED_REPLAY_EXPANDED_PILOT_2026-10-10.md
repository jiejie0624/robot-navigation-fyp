# Expanded controlled-replay pilot — 2026-10-10

## Design

This is a separate controlled planner-replay experiment, not the autonomous end-to-end benchmark. At each checkpoint, repeated A* and D* Lite receive the same current cell, goal, newly revealed obstacles, and cumulative known-obstacle set. A* searches from scratch; D* Lite retains its search state and repairs it after the same map changes. A planner-independent reachability and path validator checks each result.

The replay set has 34 deterministic traces: four hand-designed cases (single blocker, sequential blockers, off-route updates, and goal cut off) and 30 seeded generated maps (10 at each requested density: 8%, 16%, and 24%). Each trace has three checkpoints and each planner ran ten recorded repetitions. The simulator ran the set on 15 × 15 and 25 × 25 grids.

These checks establish a successful simulator run under its own validation rules; they do not by themselves establish that the planner comparison is unbiased or representative of physical environments.

## Scope and interpretation

The seeded maps broaden the earlier four-trace pilot and make the replay conditions deterministic. They are generated by the simulator's own grid generator and are not a representative sample of buildings. Repeated runs and checkpoints are nested within traces; they must not be treated as 4,080 independent maps. The study was run in one browser/device session. Although the new CSV schema records browser user-agent/platform, viewport dimensions, and device pixel ratio, this does not measure cross-device variation.

This pilot report records integrity counts only. It does not report expanded-node or timing comparisons because a fresh raw CSV export could not be retained and independently analyzed during this run. The older four-handcrafted-trace pilot remains documented separately in `CONTROLLED_REPLAY_PILOT_2026-10-09.md` with its own raw CSV and descriptive results; do not combine those measurements with this expanded pilot.

## Reproduction

The output includes trace family and seed/density fields, paired planner/checkpoint data, map configuration, path validity, and browser/device metadata. Analyze the exported file with:

```bash
python analyze_replay.py <replay-csv>
```

Retain the exported raw CSV with the report before making performance claims. Trace-family medians should be derived from per-trace summaries so multiple repetitions/checkpoints do not inflate the independent map count.
